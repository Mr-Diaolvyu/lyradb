# 系统架构设计

## 整体架构

LyraDB 采用经典的前后端分离 + 可选移动端的三层架构：

```
┌─────────────────────────────────────────────────────────┐
│                      客户端层                            │
├─────────────────┬─────────────────┬─────────────────────┤
│  Web 前端       │  Android 移动端  │  桌面打包(jpackage) │
│  Vue 3 + Vite   │  Compose 瘦客户端│  内嵌前端静态资源   │
└────────┬────────┴────────┬────────┴──────────┬──────────┘
         │ HTTP/WS         │ HTTP              │ HTTP
         ▼                 ▼                   ▼
┌─────────────────────────────────────────────────────────┐
│                    后端服务层                             │
│              Spring Boot 3.2 (Java 17)                   │
├─────────────────────────────────────────────────────────┤
│  Controller → Service → Repository                      │
│  (REST API)   (业务逻辑)  (JPA/H2 持久化)               │
├─────────────────────────────────────────────────────────┤
│  横切关注点：Security / CORS / WebSocket / 异常处理       │
└────────┬────────────────────────────────┬───────────────┘
         │ JDBC (动态驱动)                 │ SSH Tunnel
         ▼                                ▼
┌──────────────────┐          ┌──────────────────────┐
│  目标数据库       │          │  跳板机 / 内网数据库  │
│  MySQL/PG/Oracle │          │  (Apache MINA SSHD)  │
│  ClickHouse/...  │          └──────────────────────┘
└──────────────────┘
```

## 分层结构

### 后端分层

| 层 | 包路径 | 职责 |
|----|--------|------|
| Controller | `io.github.lexaquila.lyradb.controller` | REST 端点定义、请求校验、响应封装 |
| Service | `io.github.lexaquila.lyradb.service` | 核心业务逻辑、事务管理 |
| Repository | `io.github.lexaquila.lyradb.repository` | 数据访问（Spring Data JPA） |
| Model/Entity | `io.github.lexaquila.lyradb.model.entity` | JPA 实体映射 |
| Model/DTO | `io.github.lexaquila.lyradb.model.dto` | 数据传输对象 |
| Config | `io.github.lexaquila.lyradb.config` | 应用配置（安全/CORS/WS/启动引导） |
| Driver | `io.github.lexaquila.lyradb.driver` | JDBC 驱动动态下载与类加载 |

### 前端分层

| 层 | 目录 | 职责 |
|----|------|------|
| Views | `src/views/` | 页面级组件（路由入口） |
| Components | `src/components/` | 可复用 UI 组件 |
| Stores | `src/stores/` | Pinia 全局状态管理 |
| API | `src/api/` | Axios 封装，后端接口调用 |
| Types | `src/types/` | TypeScript 类型定义 |
| Utils | `src/utils/` | 工具函数（SQL 格式化等） |
| Router | `src/router/` | 路由配置与导航守卫 |

## 数据流

### 个人版数据流

```
用户操作 → Vue 组件 → Pinia Store → API 层 → 后端 Controller
    → Service → JDBC 连接目标 DB → 返回结果 → 前端渲染
```

### 企业版数据流

```
用户登录 → AuthController → Spring Security Session
    → 后续请求携带 Session Cookie
    → Controller 校验角色权限
    → Service 执行（含审计日志记录）
    → 敏感操作触发审批工作流
```

## 双版本门控机制

通过 `app.edition` 配置项（环境变量 `LYRADB_EDITION`）实现同一代码库支持两种发行版：

- **personal**（默认）：Security 全部放行，无登录页，直接展示主界面
- **enterprise**：启用 Spring Security 认证、RBAC 角色校验、审批流、审计日志

关键门控点：

- `SecurityConfig`：根据 edition 决定是否启用认证
- `EnterpriseBootstrap`：企业版启动时初始化管理员账户和默认策略
- 前端 `router/index.ts`：根据 `/app/info` 返回的 edition 决定路由模式

## 驱动管理机制

```
drivers.json（驱动注册表）
    → DriverService 解析可用驱动列表
    → Maven Resolver 从远程仓库下载 JAR
    → 缓存至 ~/.lyradb/drivers/
    → 自定义 ClassLoader 隔离加载
    → WebSocket 推送下载进度
```

## 安全架构

| 组件 | 说明 |
|------|------|
| Spring Security | 企业版 Session 认证 + HTTP Basic |
| BCrypt | 用户密码哈希存储 |
| Jasypt | 数据库连接凭据 AES 加密 |
| RBAC 角色 | `PLATFORM_ADMIN` / `DS_ADMIN` / `USER` |
| 审批工作流 | 敏感操作（DDL/导出）需审批通过后执行 |
| 审计日志 | 记录所有查询操作（用户/SQL/时间/结果） |
| 元数据防注入 | 驱动层标识符/字面量转义校验（SQLite/ClickHouse/MaxCompute） |

企业版放行端点仅限 `/auth/login`、`/drivers/**`、`/ws/**`、`/app/**`；不再放行 H2 Console 与 Swagger，其余端点均需认证。
