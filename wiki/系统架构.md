# 系统架构设计

## 交付形态

LyraDB 共用一套 Vue 前端和 Spring Boot 后端，通过 profile 与外壳形成三种交付方式。

| 形态 | 服务端位置 | edition | 访问方式 |
| --- | --- | --- | --- |
| 浏览器 BS | 独立服务器 / Docker | personal 或 enterprise | 浏览器 HTTPS |
| 桌面客户端 | jpackage 内嵌本地服务 | personal | 仅 `127.0.0.1` 随机端口 |
| 移动客户端 | 连接远端 BS | 由远端决定 | 原生 WebView + HTTPS/WSS |

移动端不运行 JDBC 驱动；Android、HarmonyOS、iOS 只是安全外壳，查询和治理仍在服务端完成。

## 组件关系

```text
浏览器 / 桌面 WebView / 移动 WebView
                  │
          Vue 3 + Pinia + API 层
                  │ HTTP(S) / WS(S)
                  ▼
Spring Security → Controller → Service → Repository
                         │             │
                         │             └─ H2 元数据库 + Flyway
                         ▼
           驱动隔离加载 / SSH 隧道
                         │
                         ▼
                  目标数据库
```

后端 API context-path 为 `/api`。打包时前端 `dist` 被嵌入 fat jar，浏览器根路径仍提供 Vue 页面，API 保持 `/api/*`。

## 后端分层

| 层 | 包 | 责任 |
| --- | --- | --- |
| Controller | `controller` | 请求校验、HTTP 协议、响应映射 |
| Service | `service` | 授权、事务、查询、审批与审计 |
| Repository | `repository` | JPA 持久化 |
| Entity / DTO | `model` | 数据模型与边界对象 |
| Config | `config` | edition、安全、CORS、启动引导 |
| Driver | `driver` | Maven Resolver 下载、缓存与隔离加载 JDBC 驱动 |

生产数据库结构由 `db/migration/` 中的 Flyway 脚本演进，Hibernate 只做 `validate`。

## 前端分层与状态边界

| 层 | 目录 | 责任 |
| --- | --- | --- |
| Views | `frontend/src/views` | 路由页面与用户流程 |
| Components | `frontend/src/components` | 可复用界面组件 |
| Stores | `frontend/src/stores` | 会话、查询编辑器等跨页面状态 |
| API | `frontend/src/api` | Axios 协议封装 |
| Utils | `frontend/src/utils` | 下载、请求竞态、确认动作等通用规则 |

查询类页面使用“只接收最后一次请求”的门控；取消请求会使旧响应失效。登录初始化失败时界面失败关闭并提供重试，不把“未知会话状态”当成匿名成功。

## edition 门控

### personal

- `dev` / `desktop` 默认使用 personal；
- 企业专属 `/auth`、`/admin`、`/approvals`、`/audit`、`/grants`、`/ent`、`/ai` 端点被拒绝；
- 仅用于本机个人场景，桌面 profile 强制随机回环端口；托盘一次性令牌交换出的 proof 只存 `sessionStorage`，API header / WebSocket query 必须与同一 HttpOnly Session 一起校验。
- 独立根静态 Context 仅公开 dist 白名单，并发送 CSP、安全响应头与分层缓存策略；业务能力仍全部位于 `/api` 门禁之后。

### enterprise

- `prod` 与 Docker 默认使用 enterprise；
- personal 直连端点 `/connections`、`/query`、`/metadata`、`/history`、`/migration`、`/tasks`、`/reports` 被拒绝；
- 无用户空库必须通过环境变量创建首个管理员，没有 `admin/admin` 兜底；
- 只有 `/app/info`、`/auth/csrf`、`/auth/login` 和 `/error` 匿名可访问；
- H2 Console 被拒绝，HTTP Basic 与 Spring form login 均关闭。

## 企业认证与授权

企业认证使用 Spring Security Session：

1. 前端先获取 `/auth/csrf`；
2. 登录请求携带 `X-XSRF-TOKEN`；
3. 认证成功后更换 Session ID，后续使用 HttpOnly 会话 Cookie；
4. 生产 Cookie 为 Secure、SameSite=Strict；
5. 用户密码或启用状态变化会递增凭据版本，旧会话在下一请求立即失效。

密码使用 BCrypt 哈希。新写入的连接凭据使用带版本前缀的 AES-256-GCM，每个值具有独立随机盐和 IV；历史 Jasypt 密文仅作兼容读取，并在后续保存时迁移。

角色分两层：

- `PLATFORM_ADMIN` 是平台级角色；
- `DS_ADMIN`、`STEWARD`、`ANALYST`、`AUDITOR` 按当前工作空间成员关系判定；
- 服务层同时校验当前工作空间和资源归属，不能只依赖前端菜单可见性。

## 企业导出审批

审批创建时持久化并绑定以下载荷：

```json
{
  "sql": "SELECT ...",
  "format": "csv",
  "defaultDatabase": "optional"
}
```

服务端从当前会话推导申请人、工作空间与数据源，不接受客户端伪造。审批通过后只有原申请人能够消费，最终导出的 SQL/格式/数据库必须与审批载荷一致，并通过原子状态更新保证只消费一次。

## 出站与驱动安全

- 动态 JDBC 驱动缓存至 `${user.home}/.lyradb/drivers`，Docker 中对应 `/home/lyradb/.lyradb/drivers`；
- Webhook 与自定义 AI 默认无允许主机，只有精确主机或受控通配子域可出站；
- 审计默认保存 SQL 脱敏结果/哈希，日志禁止记录密码、Cookie、令牌和完整连接串；
- 元数据标识符必须走驱动层校验/转义，不能把前端输入直接拼到 SQL。

## 部署边界

Docker 镜像以 UID/GID `10001` 运行，根文件系统只读，数据与驱动目录挂卷，端口默认只映射宿主回环地址。容器内部 `/api/app/info` 用于健康检查；外部流量应经 HTTPS 反向代理。
