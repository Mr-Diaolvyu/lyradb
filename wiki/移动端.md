# 移动端说明

## 定位

Android、HarmonyOS 与 iOS 都是轻量 WebView 外壳，不在手机上加载 JDBC 驱动，也不直接连接目标数据库。查询、授权、审批和审计全部由所连接的 LyraDB BS 服务端执行。

```text
原生外壳
  ├─ 服务端地址、设备认证、返回导航
  ├─ 受控 Blob 文件保存
  └─ 系统 WebView Cookie 存储
          │ HTTPS / WSS
          ▼
LyraDB BS 服务端
          │
          ▼
已授权的数据源
```

移动端可连接 personal 或 enterprise 服务；edition 由服务端决定。企业导出必须提交与 SQL、格式、数据源、默认数据库绑定的审批，通过后由申请人一次性消费。

## 3.0.0 安全基线

| 控制 | Android | HarmonyOS | iOS |
| --- | --- | --- | --- |
| 发布版服务端 | 仅 HTTPS | 仅 HTTPS | 仅 HTTPS |
| 本地 HTTP | 仅 debug 构建显式填写 | 不允许 | 不允许 |
| 同源限制 | 精确 scheme/host/port | ArkWeb 加载拦截 | 精确 scheme/host/port |
| 文件与混合内容 | 禁止 | 禁止 | ATS 不允许任意加载 |
| 应用锁失败策略 | 保持锁定/退出 | 保持锁定 | 保持锁定 |
| Blob 导出 | MediaStore / 应用下载目录 | 系统 Document Picker | 系统分享/存储面板 |

三端桥接都限制 Base64 载荷大小、清洗文件名，并只从受信任页面接收调用。超大结果应使用桌面浏览器或服务端流式下载，避免 WebView Base64 带来的内存放大。

## 本地存储的真实边界

| 数据 | 存储位置 | 是否敏感凭据 |
| --- | --- | --- |
| 规范化服务端页面 URL（origin 根路径 `/`） | SharedPreferences / Preferences / UserDefaults | 否，普通配置 |
| 应用锁开关 | 同上 | 否 |
| 登录会话 | 系统 WebView 的 Cookie 数据库 | 是，由 HttpOnly/Secure/SameSite Cookie 管理 |
| 数据库密码、AI Key | 不由移动外壳保存 | 服务端加密保存 |

当前实现没有把“服务端 URL 存在普通偏好里”包装成 Keystore、HUKS 或 Keychain 能力，也没有把会话令牌复制到偏好存储。退出登录并清缓存会清理 WebView 站点数据。

## 服务端配置

三端接受 HTTPS origin 或对应的 `/api` 应用路径，例如：

```text
https://db.example.com
https://db.example.com/api/
```

配置会统一规范化、保存并加载为 `https://db.example.com/`；连通性探测固定请求同源 `https://db.example.com/api/app/info`，不会把 `/api` 重复拼接。Android 与 iOS 的探测不跟随重定向；即使探测结果异常，WebView 的同源策略仍会阻止跳转到其他源。

Android 模拟器调试本机 HTTP 服务时，只能使用 debug 构建并显式填写 `http://10.0.2.2:8080/`。这条例外不会进入 release Manifest。

## Blob 导出桥

前端统一通过 `frontend/src/utils/download.ts` 保存文件：

- 普通浏览器使用短生命周期 Object URL；
- Android 调用 `window.LyraDBAndroid.saveBase64(...)`；
- HarmonyOS 调用 `window.LyraDBHarmony.saveBase64(...)`，由系统 Document Picker 选择保存位置；
- iOS 调用 `window.webkit.messageHandlers.lyradbDownload.postMessage(...)`。

原生桥不会接收任意文件路径。文件名只保留安全字符，iOS 使用独立临时目录并在分享结束后清理。

## 应用锁

应用锁使用系统设备认证：

- Android：`BiometricPrompt`；
- HarmonyOS：`@ohos.userIAM.userAuth`；
- iOS：`LocalAuthentication`。

启用应用锁前先完成一次设备认证。设备未配置认证能力、API 异常、用户取消或认证失败时都不会自动放行。应用锁只保护外壳启动入口，不替代服务端会话过期、RBAC 和审批校验。

## 构建与验证状态

| 平台 | 工程 | 自动化状态 |
| --- | --- | --- |
| Android | `mobile/android` | PR CI 运行 lint、测试任务与 Debug APK 构建 |
| HarmonyOS | `mobile/harmony` | 当前 Windows 环境无 DevEco 工具链，需 DevEco Studio 编译/真机验证 |
| iOS | `mobile/ios` | 当前 Windows 环境无 Xcode，需 macOS 生成工程并真机验证 |

Android CI 不能替代 release 签名、证书链、下载目录与生物识别真机测试。HarmonyOS 的系统文件 Picker、iOS 的分享面板也必须在目标 OS 版本上复核。

## 发布前检查

- 服务端使用可信 HTTPS 证书，WSS 也能连接；
- 三端最终加载规范化的 origin 根路径 `/`，探测 `origin/api/app/info`；
- 跨源导航、`file://` 与混合内容均被阻止；
- Cookie 为 HttpOnly，生产为 Secure，CORS 与公开来源一致；
- 用户取消设备认证后仍保持锁定；
- CSV/JSON 导出能够保存，取消 Picker 不产生文件；
- 大文件触发限制并给出可理解提示；
- 切换服务端和清缓存后旧会话不可继续使用；
- 企业审批的 SQL/格式/数据源与最终导出完全一致，且只能消费一次。
