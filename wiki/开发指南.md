# 开发指南

## 工具链

| 工具 | 版本 |
| --- | --- |
| JDK | 17+；桌面打包需带 `jpackage` 的 JDK 21 |
| Maven | 3.8+ |
| Node.js / npm | Node.js 20，使用仓库锁文件 |
| Android | Android Studio / SDK 34，Gradle 8.2.1 |
| HarmonyOS | DevEco Studio，项目声明 API 5.0.0 |
| iOS | macOS、Xcode 15+、XcodeGen |

## 本地开发

后端：

```bash
cd backend
mvn spring-boot:run
```

默认 `dev + personal`，仅绑定回环地址。企业行为应使用明确配置的测试环境，不要把 dev 默认密钥用于共享服务器。

前端：

```bash
cd frontend
npm ci
npm run dev
```

前端开发服务器把 `/api` 和 WebSocket 代理到 `localhost:8080`。

## 提交前质量门禁

```bash
cd frontend
npm run lint
npm run typecheck
npm run test
npm run build
```

```bash
cd backend
mvn -B -ntp clean verify
```

前端 Vitest 当前覆盖：

- 只接收最新查询响应，取消后旧响应不能回写；
- 仅对真实未认证响应触发会话失效；
- 用户取消确认/输入时不发送写请求。

新增异步页面时，应把“最后一次请求生效”和“取消不写入”作为回归测试，而不是只验证成功路径。

## 代码约定

- Vue 使用 `<script setup lang="ts">`，API 统一放在 `frontend/src/api/`。
- 共享并发/确认逻辑放在 `frontend/src/utils/`，避免页面自行实现不同语义。
- 后端控制器只做协议边界，授权与事务性规则放在 service。
- 数据库结构变化必须新增 Flyway 迁移；生产禁止 Hibernate 自动改表。
- 任何日志不得输出密码、Cookie、令牌、完整 Axios 错误对象或连接串凭据。

## 打包脚本

服务端：

```bash
bash package-server.sh 3.0.0
```

```powershell
.\package-server.ps1 -Version 3.0.0
```

桌面端：

```bash
bash package-desktop.sh 3.0.0
```

```powershell
.\package-desktop.ps1 -Version 3.0.0
```

脚本执行顺序为：

1. `npm ci`；
2. 前端 lint、类型检查、测试与生产构建；
3. 复制 `dist` 到后端静态资源目录；
4. `mvn clean verify`；
5. 桌面脚本通过 `jpackage` 生成 app-image，PowerShell 版本再生成 zip。

脚本会检查每个原生命令退出码和最终产物，不再使用 `-DskipTests`。清理静态目录前会验证目标仍位于后端 resources 目录内。

## PR CI

`.github/workflows/ci.yml` 对 PR 与 `main` push 执行：

- 前端 lint、类型检查、Vitest 与构建；
- 后端 `mvn clean verify`；
- 使用占位 CI 值校验 Compose，并从空命名卷构建、启动企业镜像，验证固定 `10001:10001` 用户与 `/api/app/info` 健康状态；
- Android lint、单元测试任务与 Debug APK 构建。

第三方 Actions 固定到完整提交 SHA，工作流默认只有 `contents: read`。本机仍应在具备 Docker 运行资源时复核反向代理、持久卷升级与恢复流程。

## 标签发布

发布标签必须是严格的 `vX.Y.Z`，且以下版本必须完全一致：

- `backend/pom.xml` 的 `revision`；
- `frontend/package.json`；
- Android `versionName`；
- iOS `CFBundleShortVersionString`；
- HarmonyOS `versionName`。

示例：

```bash
git tag v3.0.0
git push origin v3.0.0
```

Release 工作流先以只读权限完成测试与构建，再由独立 `publish` job 获得 `contents: write`。发布附件包括：

| 文件 | 说明 |
| --- | --- |
| `LyraDB-<ver>-windows-x64-portable.zip` | Windows 便携包 |
| `lyradb-backend-<ver>.jar` | 内嵌前端的服务端 |
| `lyradb-frontend-<ver>.cdx.json` | npm CycloneDX SBOM |
| `lyradb-backend-<ver>.cdx.json` | Maven CycloneDX SBOM |
| `SHA256SUMS.txt` | 上述文件的 SHA-256 |

独立 `attest` job 使用固定 SHA 的官方 `actions/attest` 生成 Sigstore/SLSA 来源证明；只有该 job 获得 `id-token: write` 与 `attestations: write`。发布 job 必须等待证明成功，仓库计划不支持 attestation 时会失败关闭，不会绕过后继续发布。下载附件后可使用 `gh attestation verify <文件> --repo <owner/repo>` 验证来源。

## Docker 部署复核

```bash
cp .env.example .env
# 替换占位值
docker compose config
docker compose build
docker compose up -d
docker compose ps
```

Dockerfile 的前端阶段同样强制执行 `npm ci`、lint、typecheck、Vitest 与生产构建；随后后端执行 `mvn clean verify`，任一门禁失败都不会产出运行镜像。

上线前至少验证：

- 容器健康状态为 `healthy`；
- 宿主机只监听回环端口，外部访问经 HTTPS 反向代理；
- Secure Cookie、CORS 来源与公开域名一致；
- 首次管理员能登录且没有默认弱口令；
- Flyway 完成，Hibernate `validate` 通过；
- `/app/data` 与驱动缓存卷在重建容器后仍存在；
- Webhook/AI 未配置白名单时出站请求被拒绝。

## 移动端验证

- Android：CI 构建 Debug APK；发布签名、HTTPS 真机、系统下载目录仍需发布前测试。
- iOS：在 macOS 执行 `xcodegen generate`，再用 Xcode 编译与真机验证。
- HarmonyOS：在 DevEco Studio Sync、编译并真机验证系统文件 Picker。

移动发布版只接受 HTTPS。Android 的明文 HTTP 仅限 debug 构建且必须显式输入；iOS 与 HarmonyOS 源码始终要求 HTTPS。
