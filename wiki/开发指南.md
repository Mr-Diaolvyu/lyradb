# 开发指南

## 工具链

| 工具 | 版本 |
| --- | --- |
| JDK | 编译使用 17+；Windows 原生打包使用带 `jpackage` 的 JDK 21 |
| Maven | 3.8+ |
| Node.js / npm | Node.js 20+，依赖必须按锁文件安装 |
| Android | SDK 34、Gradle 8.2.1 |
| HarmonyOS | DevEco Studio |
| iOS | macOS、Xcode 15+、XcodeGen |

## Java 模块

```text
root pom
├── core
├── backend
└── desktop
```

修改共享驱动、模型或 SQL 安全规则时放在 `core`，并同时运行 backend 与 desktop 测试。桌面 UI、本地状态和个人 AI 只能放在 `desktop`；企业认证、授权和 REST 能力只能放在 `backend`。

## 个人版原生桌面开发

入口：

```text
desktop/src/main/java/io/github/lexaquila/lyradb/desktop/NativeDesktopApplication.java
```

测试：

```bash
mvn -B -ntp -pl desktop -am clean verify
```

Windows 完整打包与真实 EXE 冒烟：

```powershell
.\package-desktop.ps1 -Version 3.0.1
```

Linux/macOS 原生 app-image：

```bash
bash package-desktop.sh 3.0.1
```

平台产物目录：

- Linux：`desktop/target/desktop/LyraDB/`；
- macOS：`desktop/target/desktop/LyraDB.app/`。

桌面脚本只构建 `core + desktop`，不安装 Node.js 依赖、不复制 Vue 静态资源、不运行 Spring Boot。生成 app-image 后，脚本会在冒烟测试之外独立执行：

- 依赖文件名扫描，拒绝 backend、Web 服务容器和嵌入式浏览器依赖；
- `jar tf` 内容扫描，拒绝 WebView/CEF/JxBrowser/Playwright 类；
- `jdeps` 核心字节码扫描，拒绝浏览器、本地 HTTP 服务和 Spring Boot B/S 启动入口。

PowerShell 脚本还会生成：

```text
desktop/target/LyraDB-3.0.1-windows-x64-portable.zip
```

新增桌面能力时至少验证：

- Swing 事件线程不执行网络、驱动下载或数据库阻塞操作；
- 敏感字段落盘前加密，原始 JSON 不含明文；
- AI 输出不触发 SQL 自动执行；
- 危险 SQL 需要明确二次确认；
- EXE 冒烟仍明确为无浏览器、无 WebView、无本地 HTTP 服务。

## 企业版开发

前端：

```bash
cd frontend
npm ci
npm run dev
```

共享核心与企业后端：

```bash
# 仓库根目录
mvn -B -ntp -pl backend -am clean verify
```

生产构建：

```powershell
.\package-server.ps1 -Version 3.0.1
```

```bash
bash package-server.sh 3.0.1
```

服务端脚本执行前端 lint、类型检查、测试和构建，将 `dist` 嵌入企业后端 JAR，再验证 `core + backend`。

## 提交前质量门禁

```bash
mvn -B -ntp -pl desktop -am clean verify
mvn -B -ntp -pl backend -am clean verify
```

```bash
cd frontend
npm ci
npm run lint
npm run typecheck
npm run test
npm run build
```

桌面测试当前覆盖：

- AES-256-GCM 加解密、篡改拒绝和明文敏感值失败关闭；
- AI Base URL 安全与 OpenAI 兼容响应解析；
- 真实 H2 JDBC 的 Schema / 表 / 字段导航、SQL、危险语句拦截和事务回滚；
- 9 类驱动注册；
- 桌面模块不包含常见浏览器容器。

## CI

`.github/workflows/ci.yml` 分为：

- 企业前端质量门禁；
- `core + backend` 测试、Compose 校验和企业容器启动；
- Windows `core + desktop` 构建、独立依赖/字节码扫描、真实 EXE 原生架构冒烟和 ZIP 上传；
- Android lint、单元测试与 Debug APK。

企业 B/S 通过不代表原生桌面通过，反之亦然。

## 标签发布

发布标签必须是 `vX.Y.Z`，并与以下版本一致：

- 根、`core`、`backend`、`desktop` POM 的 `revision`；
- `frontend/package.json`、`frontend/package-lock.json` 顶层版本及根包版本；
- Android、iOS、HarmonyOS 的版本名；
- 三个移动端的构建号，计算规则为 `major × 1,000,000 + minor × 1,000 + patch`。

`v3.0.0` 已发布且标签不移动。原生桌面修正版使用：

```bash
git tag v3.0.1
git push origin v3.0.1
```

Release 附件：

| 文件 | 说明 |
| --- | --- |
| `LyraDB-<ver>-windows-x64-portable.zip` | 个人版原生 Windows 客户端 |
| `lyradb-backend-<ver>.jar` | 企业版 B/S 服务端 |
| `lyradb-frontend-<ver>.cdx.json` | npm CycloneDX SBOM |
| `lyradb-java-<ver>.cdx.json` | core、desktop、backend 聚合 Maven SBOM |
| `SHA256SUMS.txt` | 发布附件 SHA-256（UTF-8 无 BOM、LF 换行） |

来源证明生成前，Ubuntu job 必须先执行 `sha256sum --check SHA256SUMS.txt`；校验失败时不得证明或发布。

发布工作流先用只读权限构建和验证，再生成来源证明，最后由独立 job 获取 `contents: write` 发布。

## Docker 企业部署复核

```bash
cp .env.example .env
docker compose config
docker compose build
docker compose up -d
docker compose ps
```
