# 开发指南

## 环境要求

| 工具 | 版本 | 说明 |
| ------ | ------ | ------ |
| JDK | 17+ | 后端编译运行 |
| Maven | 3.8+ | 后端构建 |
| Node.js | 18+ | 前端构建 |
| npm | 9+ | 前端包管理 |
| Android Studio | 最新 | Android 移动端外壳开发（可选） |
| DevEco Studio | NEXT / API 12+ | 鸿蒙 NEXT 移动端外壳开发（可选） |
| Xcode | 15+（需 macOS） | iOS 移动端外壳开发（可选） |

## 后端开发

### 启动后端

```bash
cd backend

# 开发模式（个人版，默认）
mvn spring-boot:run

# 企业版模式
set LYRADB_EDITION=enterprise
mvn spring-boot:run

# 或指定 profile
mvn spring-boot:run -Dspring-boot.run.profiles=dev
```

启动后访问：

- API: `http://localhost:8080/api`
- H2 Console（dev）: `http://localhost:8080/api/h2-console`

### 后端构建

```bash
cd backend

# 编译打包
mvn clean package -DskipTests

# 运行测试
mvn test

# 桌面 app-image 打包（需先准备前端静态资源）
mvn -Pdesktop package

# Windows MSI 安装包（需安装 WiX Toolset）
mvn -Pdesktop-msi package
```

### 后端目录约定

- 新增 REST 端点 → `controller/` 包
- 业务逻辑 → `service/` 包
- 数据访问 → `repository/` 包
- JPA 实体 → `model/entity/` 包
- DTO → `model/dto/` 包

## 前端开发

### 启动前端

```bash
cd frontend

# 安装依赖
npm install

# 开发模式（热重载）
npm run dev
```

开发服务器: `http://localhost:5173`（自动代理 `/api` 到后端 8080）

### 前端构建

```bash
cd frontend

# 类型检查 + 生产构建
npm run build

# 预览生产构建
npm run preview
```

构建产物输出到 `frontend/dist/`。

### 前端开发约定

- 组件使用 `<script setup lang="ts">` 组合式 API
- 状态管理使用 Pinia Store
- API 调用统一通过 `src/api/` 层封装
- 类型定义放在 `src/types/`
- 样式使用 CSS 变量（Design Token），定义在 `src/styles/tokens.css`

## 桌面打包

完整打包流程（使用 `package-desktop.sh`）：

1. 前端构建 → `frontend/dist/`
2. 复制 dist 到 `backend/src/main/resources/static/`
3. Maven 打包 + jpackage 生成 app-image

```bash
# Windows 下使用 Git Bash 或 WSL 执行
bash package-desktop.sh
```

## BS 架构版本服务端打包与部署

BS 架构版本以**单 fat jar** 部署：前端构建产物内嵌到 `backend/.../static`，与后端同 jar 运行。后端通过 `StaticResourceConfig` 在根路径 `/` 挂载一个独立 Tomcat 上下文服务前端页面（API 仍在 `/api`），使浏览器访问 `http://<host>:8080` 即得前端、同源调 `/api`。

一键打包脚本：

```bash
# Linux / macOS / Git Bash
bash package-server.sh

# Windows PowerShell
powershell -ExecutionPolicy Bypass -File .\package-server.ps1
```

脚本流程：前端 `npm run build` → 复制 `dist` 到 `backend/.../static` → `mvn clean package` 产出 `backend/target/lyradb-backend-1.0.0-SNAPSHOT.jar`。

部署运行：

```bash
# 个人版（默认）
java -jar lyradb-backend-1.0.0-SNAPSHOT.jar

# 企业版
LYRADB_EDITION=enterprise java -jar lyradb-backend-1.0.0-SNAPSHOT.jar

# 生产环境建议
SPRING_PROFILES_ACTIVE=prod JASYPT_PASSWORD=<口令> LYRADB_EDITION=enterprise java -jar lyradb-backend-1.0.0-SNAPSHOT.jar
```

启动后浏览器访问 `http://<host>:8080`（企业版默认账号 `admin/admin`，请立即改密）。移动端 App（Android / 鸿蒙 / iOS）亦连接此地址。

### Docker 部署

项目根目录提供三阶段构建的 `Dockerfile`（前端构建 → 后端打包 → JRE 运行镜像）与 `docker-compose.yml`：

```bash
# 方式一：直接构建 + 运行
docker build -t lyradb .
docker run -d -p 8080:8080 -e JASYPT_PASSWORD=<口令> -v lyradb-data:/app/data lyradb

# 方式二：Compose（推荐，先在 .env 中配置 JASYPT_PASSWORD）
docker compose up -d
```

数据卷：`/app/data`（H2 数据库）、`/root/.lyradb`（驱动缓存）。详细环境变量见《配置说明》。

> 注意：`StaticResourceConfig` 启动时会把 `classpath:/static/**` 抽取到临时目录并用 `DirResourceSet` 服务，同时为独立根上下文显式补充 MIME 映射（Tomcat 10.1 独立上下文不继承默认 `web.xml` 的 mime-mapping，缺失会导致 `.js` 返回空 MIME 被浏览器拒绝）。若 jar 内无前端资源（纯 API / 开发模式），则跳过根上下文。

## 移动端外壳构建

三端外壳均为 BS 封装客户端（原生外壳 + WebView 加载 BS 前端），复用同一套前端与后端内核：

| 平台 | 工程目录 | 构建 / 运行 |
| ------ | ---------- | ------------- |
| Android | `mobile/android` | Android Studio 打开 → Sync Gradle → 运行 |
| 鸿蒙 NEXT | `mobile/harmony` | DevEco Studio 打开 → Sync → 运行 |
| iOS | `mobile/ios` | `xcodegen generate` 生成工程 → Xcode 签名运行（需 macOS） |

首次启动填写 BS 服务端地址（个人自托管或企业）→ 测试连接 → 进入。详见各端 `README.md`。

## 企业版默认账户

企业版首次启动时，`EnterpriseBootstrap` 自动创建：

- 用户名: `admin`
- 密码: `admin`
- 角色: `PLATFORM_ADMIN`

> 生产环境务必修改默认密码。

## 常见问题

### 驱动下载失败

- 检查网络是否可访问 Maven Central / 阿里云镜像
- 驱动缓存目录: `~/.lyradb/drivers/`
- 可手动下载 JAR 放入缓存目录

### H2 数据库锁定

- 确保没有多个后端实例同时运行
- 数据文件: `backend/data/lyradb.mv.db`
- 删除 `.mv.db` 和 `.trace.db` 可重置数据

### 前端代理不生效

- 确认后端已启动在 8080 端口
- 检查 `vite.config.ts` 中 proxy 配置
