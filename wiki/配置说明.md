# 配置说明

> 本文描述 [LyraDB · 天琴智库](../docs/product/产品定位.md) 的运行配置；定位升级不改变安全默认值或 Feature Flag。

## Profile 与安全边界

| Profile | edition 默认值 | 监听/用途 | 数据库结构 |
| --- | --- | --- | --- |
| `dev` | `personal` | 企业后端兼容/开发模式，仅用于本机调试 | Flyway 迁移 + Hibernate `validate` |
| `desktop` | `personal` | 旧 B/S 桌面包装 profile，已禁用且不发布 | 不适用 |
| `prod` | `enterprise` | 企业部署 | Flyway 迁移 + Hibernate `validate` |

`dev` 不提供默认主密钥。生产环境不会回退到默认管理员或默认密钥。个人原生桌面不读取 Spring Profile。

## 个人原生桌面配置

默认数据目录：

```text
%USERPROFILE%\.lyradb\desktop
```

| 路径 | 内容 |
| --- | --- |
| `desktop-state.json` | 连接元数据、界面偏好、加密后的数据库密码和 AI Key |
| `master.key` | 随机 AES-256 主密钥，ACL/文件权限收紧到当前用户 |
| `drivers/` | 动态数据库驱动缓存 |
| `logs/` | 个人版滚动日志 |

测试或便携诊断可传入 `--data-dir=<绝对路径>`；正常用户不需要配置。桌面程序不读取 `LYRADB_EDITION`、CORS、Cookie、Spring Server Port 或企业引导管理员变量。

个人 AI 在原生菜单中配置。Base URL 必须为 HTTPS；只有回环地址允许 HTTP。本地状态保护不能替代 Windows 账户安全、BitLocker 等磁盘加密和终端防护。

## 生产环境变量

| 变量 | 默认值 | 要求与含义 |
| --- | --- | --- |
| `SPRING_PROFILES_ACTIVE` | `dev` | 生产必须设为 `prod`；Compose 已固定 |
| `LYRADB_EDITION` | 公共配置为 `personal`；prod 为 `enterprise` | `personal` / `enterprise` |
| `LYRADB_H2_PATH` | `./data/lyradb` | H2 元数据库文件前缀 |
| `LYRADB_DB_USER` | `sa` | H2 用户 |
| `LYRADB_DB_PASSWORD` | prod 无默认 | 生产必填，且应与 Jasypt 密钥不同 |
| `JASYPT_PASSWORD` | prod 无默认 | 数据源凭据加密密钥，生产必填 |
| `LYRADB_BOOTSTRAP_ADMIN_USERNAME` | 无 | 企业空库首次启动必填 |
| `LYRADB_BOOTSTRAP_ADMIN_PASSWORD` | 无 | 企业空库首次启动必填；12–128 位，须含大小写、数字、特殊字符，不得包含用户名 |
| `LYRADB_BOOTSTRAP_ADMIN_DISPLAY_NAME` | `平台管理员` | 初始管理员显示名 |
| `LYRADB_BOOTSTRAP_ADMIN_EMAIL` | 空 | 初始管理员邮箱 |
| `LYRADB_COOKIE_SECURE` | prod 为 `true` | HTTPS 部署保持 `true`；仅回环 HTTP 验证时显式设为 `false` |
| `LYRADB_SESSION_TIMEOUT` | `30m` | 企业会话超时 |
| `CORS_ALLOWED_ORIGINS` | prod 为空 | 浏览器精确来源，多项逗号分隔；生产需显式配置 |
| `LYRADB_WEBHOOK_ALLOWED_HOSTS` | 空 | Webhook 出站主机白名单；空表示禁用 |
| `LYRADB_AI_ALLOWED_HOSTS` | 空 | 自定义 AI 出站主机白名单；空表示禁用 |
| `LYRADB_AUDIT_MASK_SQL` | `true` | 审计日志 SQL 脱敏 |
| `LYRADB_H2_CONSOLE_ENABLED` | `false` | 仅 dev 可按需启用 H2 Console |

出站白名单支持精确主机和受控的 `*.example.com` 子域模式，不接受任意 URL。不要把协议、路径或凭据写入主机白名单。

## Cookie、CSRF 与 CORS

企业会话 Cookie 为 `HttpOnly`、`SameSite=Strict`，生产默认 `Secure`。前端在登录前获取 `/api/auth/csrf`，写请求通过 `X-XSRF-TOKEN` 提交 CSRF 令牌。CORS 必须填写浏览器实际访问的来源，例如：

```dotenv
CORS_ALLOWED_ORIGINS=https://db.example.com
LYRADB_COOKIE_SECURE=true
```

若直接在本机通过 HTTP 访问容器，必须同时显式降低 Cookie 设置并匹配来源：

```dotenv
CORS_ALLOWED_ORIGINS=http://localhost:8080
LYRADB_COOKIE_SECURE=false
```

该方式只用于回环地址验证，不应对外网开放。

## 数据库迁移

生产 profile 使用 Flyway 执行 `backend/src/main/resources/db/migration/` 下的版本化迁移，Hibernate 仅做 `validate`。不要在生产设置 `ddl-auto=update`，也不要手工跳过失败迁移。

升级前应备份 `/app/data`，先在副本上验证迁移，再滚动发布。H2 文件数据库不支持多个应用实例同时写入同一卷。

## Docker Compose

```bash
cp .env.example .env
# 替换占位值
docker compose config
docker compose up -d
docker compose ps
```

安全默认值：

- 仅映射 `127.0.0.1:${LYRADB_PORT:-8080}`，由同机 HTTPS 反向代理对外服务；
- 运行用户为 UID/GID `10001`，根文件系统只读并移除 Linux capabilities；
- `/app/data` 持久化 H2，`/home/lyradb/.lyradb` 持久化动态驱动；
- `/tmp` 使用受限 tmpfs；
- `/api/app/info` 用作容器健康检查；
- 缺少 Jasypt、H2 或 CORS 变量时拒绝启动；企业空用户库还要求初始管理员变量，初始化成功后应移除。

仓库自带 Compose 文件只交付企业版，不支持覆盖 `LYRADB_EDITION=personal` 后当作个人桌面部署。个人版应使用 Release 中的原生 Windows 便携包。

`.env` 已被 Git 忽略；`.env.example` 只能放占位值。生产更推荐由编排平台的 Secret 能力注入环境变量。

## 应用核心配置

公共默认值：

```yaml
server:
  port: 8080
  servlet:
    context-path: /api

app:
  version: 3.1.2
  driver-cache-dir: ${user.home}/.lyradb/drivers
  max-connections-per-db: 10
  max-query-rows: 10000
  query-timeout-seconds: 60
```

新保存的连接凭据使用带版本前缀的 AES-256-GCM；`PBEWithMD5AndDES` 只用于读取历史 Jasypt 密文。主密钥轮换前必须设计受控解密、重加密与回滚流程，不能直接替换导致历史凭据不可恢复。

## 企业托管数据源账号

连接企业数据源时，应为 LyraDB 创建按用途隔离的数据库账号：

- 只授予业务需要的 Schema/Table（必要时精确到列）以及 SELECT 或经批准的 DML 能力；LyraDB Grant 的 `allowedTables` 使用 `schema.table` 或 `catalog.schema.table`，不要用裸 `users` 表示多个 Schema 下的同名表；
- 撤销文件读写、外部网络、操作系统命令、用户/角色管理、授权转授、实例管理，以及目标数据库提供的危险存储过程、扩展和例程权限；
- 不使用超级用户、库所有者或 DBA 账号作为日常托管凭据；权限变更后用真实服务账号执行允许与拒绝测试。

SQL 使用未限定表名时，只有明确 defaultDatabase/default schema 且服务端能唯一归一为完整名称才允许，否则失败关闭。

JDBC `Connection.setReadOnly(true)` 只是驱动提示，不能代替数据库原生授权。服务端的 SQL AST、完整表引用校验和函数白名单属于纵深防御；数据库账号的最小权限才是应用层控制失效时的最终边界。

## 前端配置

开发服务器位于 `http://localhost:5173`，`/api` 与 WebSocket 代理到后端 `8080`。生产构建输出 `frontend/dist/`，打包脚本会复制到后端 `static` 资源目录。

前端本地只保存主题、密度等非敏感偏好。登录会话使用服务器签发的 HttpOnly Cookie，不把访问令牌或数据库密码写入 localStorage。
