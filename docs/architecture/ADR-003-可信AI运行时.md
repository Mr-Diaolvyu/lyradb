# ADR-003：可信 AI 运行时采用单编排器与类型化工具

- 产品定位：[LyraDB · 天琴智库](../product/产品定位.md)

- 状态：接受
- 日期：2026-08-03
- 基线：LyraDB 3.1.2

## 背景

LyraDB 已拥有数据库驱动、元数据快照、企业授权、SQL AST 校验、审批、脱敏和审计。直接引入可自由调用数据库的多 Agent，会复制这些边界并增加权限漂移、成本失控和结果不可追溯的风险。

## 决策

采用一个受治理的编排器和一组类型化工具。模型只负责提出计划或选择已声明工具；宿主服务负责身份、授权、任务范围、风险、时间、成本、取消、审计和结果裁剪。

每次工具调用必须满足以下交集：

`用户当前权限 ∩ Agent 授权 ∩ 本次任务范围 ∩ 数据源/分类策略 ∩ 时间与成本预算`

运行时顺序固定为：

1. 解析任务并生成计划。
2. 对 SQL、资源和风险进行服务端预检。
3. 生成不可变的任务级权限包络与计划摘要。
4. 对需要读取数据的计划要求用户确认计划摘要。
5. 每个工具调用再次校验权限包络；取消、过期或超预算时失败关闭。
6. 结果经脱敏和行数裁剪后返回，并生成证据与上下文回执。

## 风险等级

- R0：纯推理或本地格式化，不接触数据源。
- R1：读取授权元数据。
- R2：读取授权数据，必须有计划确认、行数和成本预算。
- R3：可逆写入，3.x 不开放给 AI。
- R4：DDL、不可逆写入或外部副作用，3.x 永久拒绝。

## 后果

- 复用现有企业查询治理链，不另建绕过通道。
- 工具协议可供桌面、Web 与未来 MCP/API 网关复用。
- 初期不追求复杂多 Agent 协作；只有评测证明单编排器无法达到目标时才增加角色任务。
- 4.0 写入能力必须另行通过门禁，不能通过修改提示词或前端开关启用。
