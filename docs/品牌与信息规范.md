## Brand Concept

“天琴”表达轻量、精确和协调；“智库”不是聊天框的别名，而是一个能持续积累、审核、使用和验证数据知识的系统。LyraDB 把数据库工作台保留为专业控制面，把可信知识、受控 Agent 和可追溯证据升级为产品主任务流。

品牌形象应同时表达：

- 专业：面向真实数据任务，不用消费级聊天产品语气；
- 可信：区分事实、推断、未知和未验证状态；
- 克制：不以“全自动”“零错误”或 Agent 数量制造卖点；
- 可控：用户始终知道系统看了什么、计划做什么、实际做了什么；
- 开放：支持多数据库、云与私有模型，但核心治理不绑定单一厂商。

## 信息架构

### Mission

为数据专业团队连接可信知识、受控行动与专业工具，让数据问题更快得到可复核的答案。

### Vision

让组织中的每一次数据决策，都建立在明确的语义、权限、证据和责任边界上。

### Value Proposition

对于需要跨数据库找数、理解口径、编写查询并承担治理责任的数据专业团队，LyraDB 是可私有化的可信 AI 数据智库。它把授权元数据、已验证知识、专业数据库控制面和受控 Agent 结合起来；不同于只增加聊天入口的数据库客户端或黑盒自动化 Agent，LyraDB 先找证据、再给计划、受控行动并留下回执。

### Positioning Statement

LyraDB · 天琴智库是面向数据专业团队的可信 AI 数据智库，通过已验证知识、最小权限工具和全过程证据，让人和 Agent 安全地发现、理解、查询、诊断和治理多数据库。

## 消息层级

### 一级消息

**让每个数据问题，都得到有依据、可执行、可追溯的答案。**

### 二级消息

| 消息 | 用户需求 | 可信证明 |
|---|---|---|
| 先找证据，再给答案 | 不再靠猜字段和拼上下文 | 仅审核知识进入 AI 上下文，返回 Context Receipt |
| 先给计划，再受控行动 | AI 不能越权或黑盒执行 | Grant、AST、行数、成本、确认、取消和审计 |
| 私有化且模型中立 | 数据不能被单一云模型锁定 | 本地模型、私有端点、精确白名单和 Provider 策略 |
| 多数据库，MaxCompute 有深度 | 同一团队跨引擎工作 | 共享数据库内核与 MaxCompute 专项证据链 |
| 人始终拥有控制权 | 专业任务需要检查和接管 | SQL 工作台、结果网格、审批、知识审核和失败关闭 |

## 术语规则

- 品牌全称首次出现使用“LyraDB · 天琴智库”，后续可简称“LyraDB”；
- 产品类别统一使用“可信 AI 数据智库”，不再把“数据库管理工具”或“AI 数据库工作台”作为总定位；
- “数据库工作台”只描述专业控制面，不代表完整产品类别；
- “AI 助手”仅可描述个人端具体功能，产品级入口优先使用“智库助手”或“Ask Lyra”；
- “知识”必须区分 `DRAFT`、审核中、`VERIFIED` 和已退役；
- “执行”必须说明是否只是计划、是否需要确认、是否真实完成；
- 对未完成真实环境验收的能力使用“已实现、待灰度”，不得使用“生产可用”。

## 语调

- 结论先行，随后说明证据、边界和下一步；
- 使用数据专业人员能直接判断的词，不堆叠 AI 行业黑话；
- 对风险使用明确动词：拒绝、需要确认、已取消、未验证；
- 对能力使用事实分级，不把规划写成当前功能；
- 对 AI 输出避免人格化承诺，强调系统证据与用户控制权。

## 视觉延续

本次定位迁移不更换现有视觉系统。前端当前 `tokens.css` 中的 Lyra Violet、Ink 与 Verified Green 继续作为品牌主色、专业控制面和可信状态色。若未来调整颜色，必须先更新本规范并通过设计令牌预演和事务性同步，不得在页面中分散硬编码新品牌色。

## 禁用表述

- “全自动数据库 Agent”
- “零错误”“绝对安全”“无需人工确认”
- “支持所有数据库全部能力”
- “AI 自动理解业务口径”
- “测试通过即生产可用”
- 把模型生成的 SQL、字段定义或数据结论写成已执行、已核验事实
