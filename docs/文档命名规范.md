# LyraDB 文档命名规范

当前有效的人类可读文档统一使用简体中文文件名，确保产品、研发、测试和运营人员可以直接理解文档用途。

## 命名规则

- 使用能够表达文档主题的中文短语，例如 `产品定位.md`、`AI原生接口.md`；
- 可保留通用技术缩写、产品名和版本号，例如 `AI`、`API`、`ADR-003`、`2026-08-04`；
- 同一目录下不得同时保留含义相同的中英文文件；
- 文件重命名时必须同步更新仓库内所有相对链接，并执行本地链接检查；
- 历史材料若明确要求保留原始证据，可保留原名；当前工作区已不再保留历史归档。

## 约定例外

以下名称由代码托管平台、工具链或生态约定决定，不强制中文化：

- `README.md`、`README.en.md`；
- `CONTRIBUTING.md`；
- GitHub Issue、Pull Request 模板的约定文件名；
- Qoder、Codex 等工具直接识别的规则文件；
- ADR 文件的编号前缀，例如 `ADR-003-可信AI运行时.md`。

## 校验要求

文档变更完成后至少检查：文件是否存在、旧文件名是否清零、内部链接是否可解析、`git diff --check` 是否通过。
