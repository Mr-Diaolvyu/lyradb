# LyraDB · 天琴智库产品战略

- 生效日期：2026-08-04
- 战略周期：3.x AI Native Foundation 至真实环境灰度
- 权威定位：[LyraDB 产品定位](产品定位.md)

## 1. 愿景与使命

### 愿景

让组织中的每一次数据决策，都建立在明确的语义、权限、证据和责任边界上。

### 使命

连接可信数据知识、受控行动与专业数据库工具，让数据专业团队更快得到可复核的答案。

### 战略判断

成熟数据库客户端已经覆盖大量连接、编辑和 AI 辅助能力，通用数据平台也覆盖治理与流程。LyraDB 不以功能数量正面对抗，而在“多数据库私有化 + 可验证知识 + 细粒度 Agent 治理 + MaxCompute 深度 + 本地专业控制面”的交叉区域建立优势。

## 2. 市场细分

### 首要市场

同时使用 MaxCompute 与主流关系数据库，并对私有化、数据语义、权限、成本和 AI 风险有明确要求的中国数据团队。

核心 Job Story：

> 当我面对一个跨系统的数据问题时，我希望系统先找到授权范围内的表、口径和可信问法，说明证据与未知，再给出可检查、可取消、可审计的执行计划，从而减少找数、返工和越权风险。

### 次级市场

1. 需要本地模型和离线数据边界的个人数据专业用户；
2. 需要统一管理知识、模型、权限、审批和审计的数据治理团队；
3. 希望通过 MCP/API 使用受控数据能力的 Agent 开发者。

### 不优先市场

- 通用企业文档知识库；
- 纯 BI 可视化与经营驾驶舱；
- 无人值守数据库写入自动化；
- 全数据库全功能兼容竞赛。

## 3. 相对成本

LyraDB 不追求最低模型调用价格，也不把 Token 当作核心价值单位。产品价值来自减少：

- 找表、猜字段和确认口径的时间；
- 错误 SQL、重复返工和跨工具切换；
- 越权查询、大扫描和不可追责的风险；
- 团队知识流失与重复解释。

商业成本策略是模型 BYOK 或透明转付，核心产品围绕工作空间、可信任务用户和治理能力计价；具体价格需经过用户访谈和付费实验，不在缺少证据时写死。

## 4. 价值主张

| 用户 | 使用前 | LyraDB 如何改变 | 使用后 |
|---|---|---|---|
| 数据工程师、分析师、架构师 | 在客户端、平台、文档和群聊间找信息 | Ask Lyra 组合授权元数据、已验证知识和策略，返回证据与计划 | 更快得到首次可信查询并减少口径错误 |
| 数据管理员、数据管家、审计员 | AI 分散且不可观测，只能全禁或全放 | Provider 策略、知识审核、权限包络、质量门禁和审计 | 能小范围开放 AI 并保留控制与追责 |
| 离线或私有化用户 | 云 AI 不能接触数据，本地模型缺上下文 | 原生个人端、私有模型、显式上下文和本地加密 | 在数据边界内获得可复核辅助 |
| Agent 开发者 | 直接接数据库会继承过大权限 | 独立 Gateway 身份、最小 Scope、短期令牌和类型化工具 | 安全复用知识与只读计划能力 |

## 5. 明确取舍

- 不把 AI 生成内容自动发布为已验证知识；
- 不允许模型直接执行写入、授权变更或任意 Shell/URL 工具；
- 不把原始数据值默认发送到云 Provider；
- 不先建设复杂多 Agent 通讯系统，优先单编排器和可测试工具；
- 不把所有数据库平均投入：MaxCompute 建立战略深度，MySQL/PostgreSQL/ClickHouse 建立重点生产力，其他引擎明确兼容等级；
- 不以“支持模型最多”作为卖点，核心判断是可信任务成功率；
- 不因定位升级删除 SQL 编辑器、对象浏览和结果网格，它们是必要的人类控制面。

## 6. 关键指标

### 北极星指标

**每周完成可信数据任务的活跃用户数。**

“可信数据任务”必须同时满足：用户目标明确、证据或来源可定位、权限边界通过、结果被用户接受或完成审核、关键步骤有回执。

### 当前 OMTM

**设计伙伴真实任务的可信任务成功率。**

### 护栏指标

- 未授权上下文发送次数：0；
- 未确认自动执行次数：0；
- 越权与跨工作空间泄露：0；
- 首次可信查询耗时；
- 用户修正率与失败分类；
- Provider 成本、延迟和限流率；
- 已验证知识复用率；
- 计划取消成功率和审计完整率。

## 7. 增长策略

采用“个人端 PLG + 设计伙伴共创 + 企业治理转化”的组合：

1. 个人智库工作台通过本地原生、多数据库和模型中立吸引专业用户；
2. 用户在团队协作中遇到口径复用、权限和审计问题时转向企业版；
3. 以真实任务成功案例和失败分类建立可信度，而不是宣传通用自动化；
4. 优先与 5 个设计伙伴完成至少 60 个真实任务黄金集；
5. Agent Gateway 在内部治理成熟后作为生态入口，不先作为获客噱头。

## 8. 必备能力

### 自研核心

- 统一元数据、证据、知识状态与 Context Receipt；
- 类型化工具契约和 Agent Permission Envelope；
- Grant、AST、行数、成本、确认、取消和审计链；
- 知识审核、黄金集、自动回归与质量门禁；
- 多数据库全范围 ER、真实外键与 MaxCompute 表/字段血缘、分区、成本专项证据；
- 本地/私有 Provider 安全策略和模型中立适配。

### 可合作或复用

- 基础模型与 Embedding 服务；
- 企业身份、密钥管理、可观测和部署基础设施；
- 外部数据目录，以及 DataWorks 官方元数据与血缘 OpenAPI；
- MCP 客户端与 Agent 生态。

模型负责推理，LyraDB 负责事实、权限、行动和证据。

## 9. 防御性

容易复制的是聊天界面和模型接入，难复制的是长期积累的：

- 经人工审核的字段、指标、规则和 Verified Query；
- 真实任务修正、失败分类和分引擎黄金集；
- 多数据库一致的工具契约、策略与审计证据；
- 组织权限、审批和知识责任关系；
- MaxCompute 分区、成本、任务与故障知识；
- 本地原生、私有化、多数据库和模型中立的组合交付能力。

## 关键假设与验证

| 假设 | 最小验证 |
|---|---|
| 用户愿意先维护少量高价值已验证知识 | 选择 20 个高频任务，观察知识复用率和修正率 |
| 证据与计划能提高信任而非增加负担 | 对比普通回答与带回执回答的接受率和完成时间 |
| 只读 Agent 足以创造首批付费价值 | 在隔离数据库完成计划、确认、取消和越权负例 E2E |
| MaxCompute 专项深度形成差异化 | 与 DataWorks / MaxCompute 控制台核对表血缘、字段血缘、分区、扫描量和成本偏差 |
| 企业愿意为治理而非 Token 付费 | 对设计伙伴测试工作空间与治理能力的付费意愿 |

## 当前战略边界

代码已经完成 AI 原生基础、知识、受控只读、质量、普通数据库全范围 ER、MaxCompute 表/字段血缘与 Gateway 的自动化验证，但真实 Provider、真实数据库、DataWorks 血缘权限、MaxCompute Project 和独立 MCP 客户端尚未完成灰度。因此当前对外状态是“实现完成、自动化通过、待真实环境灰度”，不升级为“生产可用”。
