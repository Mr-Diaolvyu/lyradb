# LyraDB 可信 AI 数据智库：意图—实现差距矩阵

- 产品定位：[LyraDB · 天琴智库](产品定位.md)

基线：`main@a5bd171`（LyraDB 3.1.2）
审计方法：产品意图 → 当前实现 → 缺口 → 强制执行点 → 验收证据。

## 1. 产品边界

LyraDB 的目标不是“在数据库客户端旁边增加一个聊天框”，而是成为面向数据专业团队、可私有化部署的可信 AI 数据智库：每个数据问题都应得到有依据、可执行、可追溯的回答。

以下边界是不可被提示词或前端开关绕过的服务端约束：

- 不依据字段名臆造业务口径；未核验的知识必须明确标记。
- 不把云端样本数据默认发送给模型；上下文必须显式选择并生成回执。
- 不自动执行 DML/DDL；写入型 Agent 在 4.0 门禁通过前保持关闭。
- 不继承平台管理员权限给外部 Agent 或网关身份。
- 不把 AI 建议静默发布为团队知识；发布必须经审核状态机。

## 2. 差距矩阵

| 产品意图 | 3.1.2 当前实现证据 | 关键缺口 | 本轮强制执行点 | 验收证据 |
|---|---|---|---|---|
| 回答有来源 | 元数据快照可显式附加并记录摘要 | API 没有统一证据模型与上下文回执 | `EvidenceRef`、`AiContextReceipt`；回答返回证据和上下文摘要 | 单元测试验证稳定摘要、不可变集合与必填字段 |
| 知识可信 | 授权后的元数据目录已存在 | 没有业务术语、指标、Verified Query 的审核生命周期 | 仅 `VERIFIED` 进入上下文；元数据摄取只建草稿；检索可选混合向量并记录降级 | 状态转换、摄取、嵌入、跨工作空间隔离测试 |
| Agent 可控 | 企业查询链已有 AST、Grant、审批、脱敏、审计 | 没有任务级权限包络、类型化工具、预检与取消 | 四步工具白名单；计划加密持久化、单次认领、执行前重新授权、跨节点取消 | 过期、越权、重复、重启、取消、超行数/成本负例 |

## 3. 分阶段交付定义

1. 3.2 Foundation：共享领域契约、证据模型、权限包络、类型化工具协议、Feature Flag、评测模型。
2. 3.3 Ask Lyra + Knowledge Core：知识审核、Verified Query、证据检索与 Context Receipt。
3. 3.4 Governed Read Agent：计划、预检、显式确认、只读执行、取消与回执。
4. 3.5 Team Knowledge Loop + AI Quality：建议转草稿、审核发布、黄金集与质量仪表。
5. 3.6 MaxCompute Intelligence Agent：分区感知、成本预算与任务诊断。
6. 3.7 Agent Gateway：独立身份、短期令牌、受控 API/MCP 工具面与审计。
7. 4.0 Gate Review：不预设上线；依据写入安全、回滚、审计、质量和真实环境验证决定。

## 4. 完成口径

“有类、有接口或有页面”不算完成。每项能力必须同时具备：服务端强制边界、失败关闭的负向测试、用户可见的解释/回执、可关闭的功能开关，以及不扩大既有权限的回归证据。
