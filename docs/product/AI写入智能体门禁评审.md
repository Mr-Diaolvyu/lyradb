# LyraDB 4.0 写入型 Agent 门禁评审

- 产品定位：[LyraDB · 天琴智库](产品定位.md)

- 评审日期：2026-08-03
- 当前决定：**NO-GO（不开放）**
- 技术约束：`WRITE_AGENT` 为 3.x 服务端硬门禁；没有写工具、写端点或前端入口。

## 1. 为什么不能随“全部推进”直接开放

写入数据的影响无法通过“模型回答看起来正确”证明安全。现有 LyraDB 已对人工 DML 提供审批和风险校验，但 AI 自主写入还需要任务幂等、事务边界、影响预览、回滚证明、双重确认和长周期质量证据。缺少任一项，都可能把一次幻觉放大为真实数据事故。

因此本轮只推进写入门禁设计和反向验证，不实现可调用的写入工具。

| 门禁 | 要求 | 当前证据 | 结论 |

## 3. 4.0 最低准入标准

只有下列条件全部具备可复核证据，才允许提交“将硬门禁改为可灰度开关”的独立变更：

1. 写入仅支持经过明确枚举的低风险工具，不接受模型传入任意 SQL。
2. 每次写入先产生只读影响预览，再形成包含目标资源、谓词、字段、最大行数、事务和回滚方式的不可变摘要。
3. 用户确认影响摘要后，仍需进入现有审批链；计划或权限变化会使确认失效。
4. 所有写任务强制幂等键、短时有效期、单次消费、乐观并发校验与数据库事务。
5. 每个支持方言完成成功、超限、权限回收、连接中断、部分失败、取消和回滚演练。
6. 黄金集包含越权、提示注入、宽谓词、摘要替换、重放、并发和回滚失败负例，并连续 30 天达到约定门禁。
7. 安全、数据治理、运维和产品负责人共同签署上线决定。

## 4. 下一次评审应提交的材料

- 写入威胁模型与权限矩阵。
- 类型化写工具契约和“不支持”清单。
- 各数据库事务/回滚能力矩阵。
- 预生产 E2E 报告与可重复演练脚本。
- 黄金集版本、连续质量趋势和全部失败样本。
- Kill switch、撤权、审计导出与事故恢复演练记录。

在这些材料齐备前，任何提示词、前端按钮、环境变量或 Gateway Scope 都不得开放写入能力。
